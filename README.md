# RCFI Technology website (Next.js)

The Google Stitch redesign of rcfi.co.ke, converted into a Next.js 16 (App Router) project.
Every page is a React component; the rendered design is identical to the Stitch HTML
(verified by full-page pixel comparison of all 40 pages).

## Run it

Requires Node.js 20.9 or newer.

```bash
npm install
npm run dev          # http://localhost:3000
npm run build        # production build (all routes prerendered as static pages)
npm start
```

Open `/variants/` for an index of every page and the alternate designs.

## Project structure

```
app/                         one folder per route
  layout.tsx                 root layout (Google Fonts)
  page.tsx                   / (home)
  about/page.tsx             /about/ … etc.
  products/certysign/
    page.tsx                 the page, as JSX
    scripts.ts               the page's original interactive scripts (if it has any)
  not-found.tsx              the Stitch 404 design
  variants/                  alternate designs + /variants/ index
components/PageScripts.tsx   runs a page's scripts after it mounts, cleans up on navigation
styles/pages/<page>/
  tailwind.config.js         that page's Tailwind theme, exactly as Stitch exported it
  page.css                   Tailwind + the page's own <style> block
  late.css                   (some pages) classes that only the page's scripts add
postcss/rcfi-postcss-scope/  PostCSS plugin that scopes each page's CSS to that page
lib/routes.ts                page list and titles
lib/redirects.json           alias URLs → real pages
lib/fonts.ts                 Google Fonts stylesheets
public/brand, public/images  logos and generated photos
```

## How it works

**Pages.** Each Stitch page was converted to JSX: `class` → `className`, inline styles → style
objects, form fields → uncontrolled inputs with the same initial values, whitespace kept exactly
as the browser rendered it. Internal links use `next/link`, so navigation is client-side.

**Styles.** Tailwind is compiled at build time (Tailwind 3, the same engine the Stitch CDN used).
Stitch gave every page its own theme (different values for `bg-primary`, a dark theme on some
pages), so each page keeps its own `tailwind.config.js`. The PostCSS plugin prefixes every
selector in a page's CSS with `html:has(.rcfi-<page>)`, so a page's styles only apply while that
page is on screen and themes never leak between pages.

**Interactivity.** Tabs, simulators, filters, accordions, mobile menus and form demos run the
page's original JavaScript (in `scripts.ts`), started by `<PageScripts>` after the page mounts.
Inline handlers from the HTML (`onclick="…"`) are kept as `data-rcfi-onclick` attributes and
bound the same way. Timers and listeners are removed when you navigate away. These can be
rewritten as React state page by page whenever you want; the markup doesn't need to change.

To edit a page, edit its `page.tsx`. Tailwind classes you add are picked up automatically as
long as they exist in that page's theme.

## Things to know

- **Four academy pages render with Tailwind's default theme**: Applied Data & AI, Digital Trust &
  Cyber Defence, Executive Briefings and Modern Engineering. Their Stitch config has a syntax
  error (a missing `}`), so the browser ignored it in the original HTML and in Stitch's own
  preview. That look is reproduced exactly. To give them the proper RCFI theme, open
  `styles/pages/<page>/tailwind.config.js` and change `const stitch = {};` to
  `const stitch = intended;`.
- **Links**: nav, footer and CTA links point to real routes. About 90 links with nothing to point
  to yet (API docs, Developer Hub, individual articles, social icons, PDF downloads) are `#`.
- **Images** load from `lh3.googleusercontent.com` (Stitch hosting) and may expire. Download them
  into `public/images/` and update the `src`s before launch.
- **Stats, certifications, partner names and client names** in the copy were generated by Stitch;
  check them before going live.
- **Forms** are front-end demos; they don't submit anywhere yet.
- `reactStrictMode` is off because the original scripts attach DOM listeners, and StrictMode's
  dev-only double mount would attach them twice.
- Two Stitch capture leftovers were removed (a fixed 1280px frame on the DHA page and
  `opacity: 0` on the Privacy page) along with a hidden capture-tool `<div>`; they made those
  pages unusable and aren't part of the design.
